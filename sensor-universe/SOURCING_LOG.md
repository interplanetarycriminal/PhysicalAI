# Sourcing log — September 2026

This file records where the catalog's sourcing data came from. It covers one
change: the pass that filled empty `link` fields, checked the vendor SKUs and
library names the audit had flagged VERIFY, and wrote the missing "what fools
it" notes on the outcome list.

**The standard applied.** A URL is recorded only if it was actually fetched and
the page that came back named the part. First-party pages only — the
manufacturer, or the vendor who designed the board. No marketplace listings
(Amazon, AliExpress, eBay, reseller aggregators), because those churn, and no
search-result snippets, because a snippet is not a page. Where no such page
exists, the `link` field is left null and the reason is written down here rather
than being papered over with a plausible-looking URL: `link` is rendered raw
into a workbook cell, so it can hold a URL or nothing, never an explanation.
No SKU, library name or part number anywhere in this pass was invented; a token
that could not be confirmed was either corrected to the real one or replaced
with a generic description.

Everything below was checked on 2026-09-03 and is stamped `as_of="2026-09"` in
the data.

### 3.3 The rule applied to Adafruit library tokens

The two slices reached different verdicts on tokens of the shape
`Adafruit_<PART>`, and both were right, because they were looking at two
different situations. The rule, stated once:

**A token stays as it is when it is the real header/class name and the library
exists under a suffixed repository slug. It is corrected when the name resolves
to nothing at all.**

So `Adafruit_BME280`, `Adafruit_TSL2591`, `Adafruit_MLX90393` and
`Adafruit_CAP1188` are confirmed unchanged: the repository slugs carry a
`_Library` suffix, but the token as written is the header you `#include` and the
class you instantiate, which is what a `lib` field is for. Whereas
`Adafruit_MLX90614` (S007, S117) and `Adafruit_MAX31855` (S004) are corrected to
`Adafruit-MLX90614-Library` and `Adafruit-MAX31855-library`: those underscore
forms 404 on github.com and on every raw path, with no rename-redirect, so they
name neither a repository nor a header — they resolve to nothing, and a reader
searching for them finds nothing. The same test retires `Adafruit_TLV493D`,
`Adafruit_VL53L4CD` and `Adafruit_VL53L4CX`, none of which exist in any form.
